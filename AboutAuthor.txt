A short note from the author.

I am Raveh Neeman. At the time of writing, I am an HW/SW architect working on quantum computing. 
For more, just google me.

In March 2026, I was building an AI orchestration system to make Claude, ChatGPT, 
and other local and global AI systems work together on a shared project. 
A central component of that system was shared storage: 
every non-temporary file the AIs need to access is mirrored to the cloud as it is created, updated, renamed, moved, or deleted.

As it turned out, the importance of shared storage for AI orchestration and quantum research was dwarfed within hours by more substantial challenges. 
But it had already revealed itself as an ideal case study: 
a self-contained, mid-sized software product whose production code was written by AI without a human editing the source files at all.
This file is the only one in the entire project that I typed myself, in a good old multipurpose IDE.

On-the-fly mirroring is messy. Editors save the same file ten times in five seconds. 
Build tools spawn hundreds of short-lived artifacts. Large log files grow continuously. 
Office applications write to temporary files, delete the original, then rename. 
Users reorganize directories mid-session. Cloud APIs throttle in ways that vary by provider, 
account tier, and time of day. None of the off-the-shelf sync tools I tried handled this without either 
overwhelming the connection or silently dropping work.

I built SelectiveMirror to handle this with a fair scheduling queue that deduplicates repeated events, 
prioritizes deletions, and enforces a per-file cooldown after each successful sync — 
so no single hot file can monopolize or saturate the connection. 
It filters noise through .syncignore files (with familiar .gitignore syntax), 
detects and cleans up stale remote files automatically, and performs server-side renames 
when a mirror’s remote path changes, without re-uploading a single byte.

I am pleased to release SelectiveMirror as a free and open-source utility, in the hope that it will be useful to many.

All source files were LLM-authored under my architectural and product-definition guidance. 
Verification and validation were AI-led, with me-in-the-loop review and final acceptance. 
As is typical for production software, product engineering, system verification, telemetry, and release engineering 
took roughly 80% of the project time—while coding the sync engine itself and feature-level verification accounted for the smaller share. 
A case study write-up is in preparation.

Bug reports and proposals are very welcome. Enjoy!
